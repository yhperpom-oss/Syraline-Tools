# SyraLine License Server

Online activation / validation server for SyraLine. Keys are generated by you,
bound to a machine on first activation, and re-checked every launch. Responses
are HMAC-signed so a spoofed endpoint cannot hand out a fake "ok".

## 1. Install

```bash
cd server
python -m venv .venv
. .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Configure

Copy `.env.example` to `.env` and set strong values:

| Variable         | Meaning                                                        |
|------------------|----------------------------------------------------------------|
| `LICENSE_SECRET` | Shared HMAC secret. **Must equal the client secret** (below).  |
| `ADMIN_TOKEN`    | Required by every `/admin/*` call (header `X-Admin-Token`).     |
| `SYRALINE_DB`    | Optional path to the SQLite file (default `./licenses.db`).     |

On Windows PowerShell, export them before running:

```powershell
$env:LICENSE_SECRET="<long-random-secret>"
$env:ADMIN_TOKEN="<admin-token>"
```

## 3. Run

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

Put it behind HTTPS in production (a reverse proxy such as Caddy or nginx).
The client talks plain JSON over whatever URL you configure.

## 4. Create keys

Offline, straight into the database (no running server needed):

```bash
python admin.py create --count 10 --max 1 --days 365 --note "launch batch"
python admin.py list
python admin.py revoke ABCDE-FGHJK-LMNPQ-RSTUV
python admin.py restore ABCDE-FGHJK-LMNPQ-RSTUV
```

- `--max`  = how many machines one key may activate.
- `--days` = validity window (`0` = never expires).

Or over HTTP while the server runs:

```bash
curl -X POST http://localhost:8000/admin/keys \
  -H "X-Admin-Token: $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"count":5,"max_activations":1,"expires_days":365,"note":"march"}'
```

## 5. Point the SyraLine client at it

Edit `SyraLine/SyraLine/lib/license_config.py` (or set the env vars):

```python
LICENSE_API_BASE = "https://your-server.example.com"
LICENSE_SECRET   = "<same value as the server's LICENSE_SECRET>"
```

That's it — on next launch SyraLine asks for a key, activates it against your
server, and remembers it. If a validated machine later can't reach the server,
it keeps working for `OFFLINE_GRACE_DAYS` (default 7) before requiring a recheck.

## Endpoints

| Method | Path                         | Auth           | Purpose                   |
|--------|------------------------------|----------------|---------------------------|
| GET    | `/health`                    | –              | liveness                  |
| POST   | `/api/activate`              | signed         | bind key ↔ machine        |
| POST   | `/api/validate`              | signed         | recheck key/token/machine |
| POST   | `/admin/keys`                | `X-Admin-Token`| create keys               |
| GET    | `/admin/keys`                | `X-Admin-Token`| list keys                 |
| POST   | `/admin/keys/{key}/revoke`   | `X-Admin-Token`| revoke                    |
| POST   | `/admin/keys/{key}/restore`  | `X-Admin-Token`| re-activate               |

## Security notes

- This is **tamper resistance, not unbreakable DRM**: the shared secret ships
  inside the Python client, so a determined user with the source can bypass the
  check. It stops casual sharing and lets you revoke keys centrally.
- Use a long random `LICENSE_SECRET`, keep `ADMIN_TOKEN` private, and serve the
  API over HTTPS.
- For development you can skip the gate entirely with `SYRALINE_LICENSE_SKIP=1`.
